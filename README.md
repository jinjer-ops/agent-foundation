# Agent Foundation

LLM 製品に依存しない、個人・チーム向けの AI エージェント運用基盤です。Codex と Claude Code の両方が同じ正本を参照し、製品固有の設定は薄いアダプタだけに留めます。

## 設計原則

1. **共有可能性**: 公開してもよい一般則・再利用可能なワークフローだけを置く。
2. **単一の正本**: 共通ルールと共通スキルはこのリポジトリだけで編集する。
3. **最小権限**: 接続情報、許可リスト、組織・案件・顧客データはここに置かない。
4. **層を分ける**: 基盤 → 組織プロファイル（ローカル専用）→ リポジトリ固有ルール → 一時的な会話指示の順で具体化する。
5. **検証可能性**: 重要な変更には受入条件・実行した検証・残余リスクを残す。

## 構成

| 場所 | 正本 | 内容 | 公開可否 |
| --- | --- | --- | --- |
| `AGENTS.md` | 共通グローバルルール | 安全・品質・作業の基本契約 | 可 |
| `skills/` | 共通スキル | 下の一覧 | 可 |
| `rules/` | 常時読み込むルール | 毎セッション効かせる短い規則 | 可 |
| `config/policy.json` | 公開前検査の既定設定 | 組織固有の許可リストは空。自分の設定は環境変数で差し替える | 可 |
| `agent-private/`（リポジトリ外） | 組織プロファイル | 会社・顧客・ブランド・接続先・ローカル運用 | 不可 |
| 各リポジトリの `AGENTS.md` / `CLAUDE.md` | プロジェクト固有 | 実装規約、テスト、デプロイ手順 | 原則リポジトリ方針に従う |
| `~/.codex/config.toml`, `~/.claude/settings.json` | 実行時設定 | モデル、承認、MCP、フック | 個人ローカルのみ |

## 収録しているスキル

| スキル | 何をするか |
| --- | --- |
| `audit` | 証拠に基づく監査。主張を反証してから確定する |
| `review-harshly` | 第三者として静的にレビューする。過去に見落とした欠陥パターンの点検リスト付き |
| `tabular-read` | 表・シート・テーブルを全量読まずに、形を見てから必要な列だけ取る |
| `git-publish` | 共有リポジトリへ入れる前に、文体・秘密・個人情報・実在パスを機械検査する |
| `github-publish` | リポジトリを公開する手順 |
| `agent-config-inventory` | 指示の 5 つの形を数え、「拒否する」等の主張と実態を突き合わせる |
| `project-handover` | 引き継ぎ書の作り方 |
| `codex-claude-handoff` | 設計側と実装側を分けて進めるときの受け渡し |
| `codex-implement` | 設計側のブリーフを唯一の仕様として実装し、判断が要る点で止まる |

## 収録しているルール

| ルール | 何を防ぐか |
| --- | --- |
| `rules/large-data-reads.md` | 大きいデータを全量読んで文脈を溢れさせること |

**ルールはリンクではなくコピーで置く。** 単一ファイルのため、インストーラの対象外である。
`rules/*.md` を `~/.claude/rules/` へコピーする。

## インストール

Windows の既定配置では、次を一度だけ行います。

1. `~/.codex/AGENTS.md` をこのリポジトリの `AGENTS.md` へのシンボリックリンクにする。
2. `~/.claude/CLAUDE.md` は `AGENTS.md` を import する薄いアダプタにする。
3. 各 `skills/<skill-name>` を、`~/.codex/skills/` と `~/.claude/skills/` から同じ実体へリンクする。
   ルールは `rules/*.md` を `~/.claude/rules/` へコピーする（リンクではない）。
4. 組織固有の必要がある場合だけ、両アダプタから `agent-private/AGENTS.md` を読み込む。

`scripts/verify-layout.ps1` は、参照先・秘密の混入・公開対象の状態を確認します。公開前には `github-publish` スキルを使ってください。

## 検証

```bash
cd tests && python -m unittest discover -s .
```

一時ディレクトリへ書けない実行環境では、作成先を指定する。
指定先が存在しない・書き込めない場合は、設定すべき内容を示して停止する。

```bash
PREFLIGHT_FIXTURE_ROOT=<書込み可能なディレクトリ> python -m unittest discover -s .
```

回帰テストは使い捨ての git リポジトリを組み立てて実行する。
**このリポジトリの追跡ファイルには、検査対象になる危険な文字列を置かない。**
検出させたい文字列はテストが実行時に組み立てる（`conversational_phrase` などを参照）。

## 運用

- 共通化候補は、少なくとも二つの独立したプロジェクトで使えた時点でこのリポジトリへ昇格する。
- 組織名、顧客名、社内 URL、認証方式、具体的な権限、業務定義は `agent-private` または対象リポジトリへ置く。
- 自動生成された承認履歴やセッション履歴は、設定資産ではない。Git 管理もしない。
- 新しい見落とし・事故パターンは `audit` スキルの「学習ログ」へ匿名化して追加する。

## 公開前チェック

- `git status --short` が意図どおりである。
- 組織固有名、絶対パス、個人情報、トークン、実データがない。
- 初見の利用者が README だけで導入・検証できる。
- `powershell -ExecutionPolicy Bypass -File scripts/verify-layout.ps1` が通る。
