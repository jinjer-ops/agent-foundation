# 大きいデータの読み方（常時）

サイズが大きい、または不明なデータを読む前に必ず通る規則。詳しい手順と実測値は
`tabular-read` skill にある。ここには判断に必要な最小限だけを置く。

- **形を見てから取る。** 表・シート・テーブルは、行数・列名・シート名を先に取り、
  必要な列を決めてから範囲指定で取得する。全量を読んでから絞るのは順序が逆。
- **絞り込めないなら止まる。** 範囲指定も列選択もできないと分かったら、取得方法を変える合図。
  「全部読む」の理由にはしない。
- **出力は発生源でフィルタする。** `gh api` は `-q`、`git diff` は `--stat`、`grep` は `-c`。
  既定の全文出力をそのまま流さない。一致内容が要るのか件数で足りるのかを先に決める。
- **複数ステップのデータ移動は、往復ではなく1本のスクリプトにする。** 取得→加工→書き込みを
  ツール呼び出しで往復させると、同じデータが何度も文脈を通る。スクリプトにまとめれば
  中間データは文脈へ入らず、結果だけが返る。
- **ファイルは必要な範囲だけ読む。** 数百行を超えるファイルは、該当箇所を検索してから
  オフセット指定で読む。
- **個人情報を含む列は、必要でない限り取り出さない。** サンプル表示も既定では行わない。
- **1セッション1目的。** 別目的の作業を同じ文脈に足さない。長くなったら要約して切り直す。

守れているかは「このあと何トークン入るか」で判断する。桁が変わる操作（全量読み・素の JSON・
一致行の全出力・同じデータの往復）だけを止めれば足りる。文章の圧縮や事前宣言のような儀式は
効果がない。

重い読み取りを別エージェントへ寄せて結果だけ受け取る方法もあるが、**この環境では
利用者が明示したときだけ使う。**
