# tabular-read — 表は形を見てから必要な分だけ取る

## このスキルが解く問題

表形式のデータは、全量を読むと二つの損失が同時に起きる。**コンテキストがデータで埋まり**、
**必要のない個人情報まで会話へ入る**。しかも全量を読んでも、実際に使うのは1〜2列であることが多い。

順序は常に同じ。**形を見る → 必要な範囲だけ取る → ローカルで処理して件数だけ出す。**

## 手順

1. **サイズを確かめる。** 行数・列数・シート名を先に取る。ここで数百トークンしか使わない。
   `scripts/peek_table.py <path>` は、ヘッダー名・列位置・各列の充填率・行数を出す。
   **既定では値を1つも表示しない**（`--show-values N` で明示的に出せるが、個人情報を含む列では使わない）。
2. **必要な列と行を決める。** 「どの列があれば目的を達せるか」を先に言語化する。
   目的が1列で足りるなら、他の列は取らない。
3. **範囲を指定して取る。** 下の「ソース別」に従う。範囲指定できる経路を優先し、
   全量しか返さない経路は最後の手段にする。
4. **ローカルで処理し、標準出力には件数・統計・結果だけを出す。**
   `--columns <名前> --out <file>` は、指定列をファイルへ書き、stdout には件数しか出さない。
5. **絞り込めないと分かった時点で止める。** 全量を読んでから絞るのは、順序が逆である。
   範囲指定も列選択もできないなら、それは「取得方法を変える」合図であって、
   全部読む理由にはならない。

## ソース別

| ソース | 取り方 | 避けること |
| --- | --- | --- |
| Google Sheets | Sheets API の値範囲（`values/'<シート名>'!E1:E5` で当たりを付け、次に `E:E`）。`fields` で必要なプロパティだけ | シート全体のエクスポート。tab 指定なしの CSV 変換 |
| Excel / CSV（手元） | `scripts/peek_table.py` で形を見て、`--columns` で抽出 | 全文を読み込んで会話で絞る |
| データベース・BigQuery | `LIMIT` 付きの列指定でスキーマ確認 → 集計・`COUNT`・`DISTINCT` を SQL 側で計算 | `SELECT *`。行を全部持ってきて手元で集計 |
| API / CLI | 発生源でフィルタ（`gh api -q`、`--format`、`--fields`）。件数だけ必要なら `length` | 既定の JSON 全文。1件あたり数十フィールドが入る |
| 全量しか返さないコネクタ | 保存されたファイルに対して 1・4 を適用する。列で切れない自然文レンダリングなら、取得方法自体を変える | 「保存されたから読める」を理由に全文を読む |

## 実測（2026-09-03、従業員データ 3.8MB の読み取りで発生）

| やり方 | 実測 |
| --- | --- |
| シート全体の自然文レンダリング | 2,540,708 文字（約63万トークン相当）。サイズ上限で中断 |
| 目的の1列だけ | 5〜10KB 程度 |
| API 応答を素で出す | 3件で 4.3KB（1件あたり URL テンプレート等が十数項目） |
| 同じ応答を `-q` で集計 | 約90バイト |
| grep で一致行を出す | 32.1KB |
| 同じ検索を `-c` で件数に | 60バイト |

差は 100〜700 倍で、桁が変わる。**文章を短く書く工夫より、この順序を守ることの方が効く。**

## 安全側に倒してあるところ

いずれも「静かに間違った結果を返す」より止まる方を選んでいる。

| 状況 | 挙動 |
| --- | --- |
| 列名が重複している | **抽出を拒否する。** 先頭を黙って採ると、後ろの列にしか値が無い行が落ち、件数だけは妥当に見える。peek は重複を WARNING で先に出す |
| 指定した列が無い | 拒否する。近い名前で代用しない |
| `--out` を git が追跡する場所へ向けた | 拒否する。抽出物は個人情報を含むことが多く、`git add -A` 一回で公開範囲へ入る。無視対象の場所か、`--allow-in-repo` を明示した場合だけ書く |
| ヘッダー行の指定が範囲外 | 拒否する |
| 値のサンプル表示 | 既定で出さない。`--show-values N` を明示したときだけ |

xlsx の行位置は**スプレッドシートの行番号に一致する**。空行が XML から省略されていても、
`--header-row 3` はシート上の3行目を指す。

## このスキルが保証しないもの

- `peek_table.py` は `.csv` `.tsv` `.xlsx`、および長いテキスト1本を包んだ `.json` を扱う。
  `.xls`（旧形式）、パスワード付き、数式の計算結果に依存する列は対象外。
- xlsx は共有文字列とインライン文字列を読むが、**書式・日付シリアル値を人間可読へ変換しない**。
  日付が数値で出た場合は、その列の意味を確認してから使う。
- 列名の一致は完全一致のみ。表記揺れ（全角括弧・空白）は呼び出す側で確認する。
- **抽出は絞り込みをしない。** 在籍状態などの条件で行を選ぶのは、抽出後の別の工程である。
- 追跡先の判定は git に問い合わせる。git が無い環境では判定できないため、その旨を返して書き込む。
  その環境では出力先を自分で確認する。
