# Audit learning log

Add only portable, anonymized lessons. Do not include company, customer, repository, account, or secret details.

| Condition | Failure mode | Detection | Safe default | Evidence date |
| --- | --- | --- | --- | --- |
| Moving a large active workspace on Windows | A move may copy some children but fail to remove locked or protected source children, leaving unresolved duplicates. | Compare source and destination names and counts immediately after the move. | Preserve both copies; do not delete or merge until locks are released and authoritative content is compared. | 2026-08-21 |
| An external value is fetched by a shared business key but persisted to multiple records | Advancing queue state by the shared key can mark sibling records complete even though the external write targeted only one record. | Compare primary-system write targets with queue rows advanced, including a sibling-key sample. | Advance state only by the primary record ID after every intended sibling has been acknowledged by the primary system. | 2026-08-24 |
| A guard infers membership of a managed area from a filesystem marker | An abandoned or partial marker matches, so the guard fires on ordinary destinations and the operator learns to pass the override, removing the protection. | Run the guard against the paths real usage supplies, not only a synthetic positive case. | Ask the tool that owns the concept instead of pattern-matching the filesystem. | 2026-09-03 |
| A column or field is selected by name from caller-supplied data | A duplicated name makes the tool take the first match, dropping values held only by the later one while the record count still looks plausible. | Build a fixture with a duplicated name and compare records written against records expected. | Refuse the selection and name the positions rather than choosing one. | 2026-09-03 |
| A position in a file is treated as a logical index | Formats that omit empty entries (worksheet rows, sparse exports) shift every subsequent index, so a header or key is read from the wrong place and all downstream labels are wrong. | Read a fixture whose first index is greater than one and assert which entry is reported. | Place entries at the index the format states and pad the gaps. | 2026-09-03 |
| A dataset is classified as static, hand-maintained input from documentation and repository code | An external ETL tool writes to it on a schedule and leaves no trace in the repository, so migrating or freezing it creates a path where upstream updates never reach consumers, with no error or warning. | Count writes to the object in the platform's job history over a fixed window, not only references in code. | Require zero writes over a stated window before treating anything as static; a document's classification is only true as of its writing date. | 2026-09-07 |
| Output is compared before and after a change to prove equivalence | A target that embeds execution time changes every run, so the comparison reports a false difference; an automatic revert then fails on a stale version token and leaves production in the half-changed state. | Measure the same target twice before comparing; refetch the object before any revert. | For unstable targets, compare the inputs exactly instead of the outputs, and never revert using an object handle captured before the write. | 2026-09-07 |
| A unique marker is embedded in work and then searched for in logs or history to identify the actor or path | The search query itself contains the marker literal, so it matches its own record and returns the searcher as the answer, which looks entirely plausible. | Check whether each matching row belongs to the work under test or to the search itself. | Do not write the marker literally on the search side, or exclude self by actor, time, and job kind; treat a positive match as suspect until the method is shown unable to match itself. | 2026-09-07 |
| Deletion is confirmed by checking absence immediately afterwards | An external scheduler recreates the object hours or days later; the immediate check proves it was removed, never that it stays removed. | Re-check existence after at least one full cycle of the suspected producer. | Define deletion as complete only after observing no recreation across a cycle; when the update cadence is unknown, rename and leave in place instead of deleting. | 2026-09-07 |
| A new capability is granted using an existing permission tier as the rule | The tier already conferred that capability, so nobody gains anything new; the mechanism is finished and recorded as delivered while the stated goal is untouched. | Count the people who can newly perform the action, not the people granted the role. | State acceptance as a number of people who could not do it before and now can. | 2026-09-07 |
| A pre-deletion reference check enumerates the places to scan | Another actor moves the referencing logic into a newly created namespace, so the check passes over a scope that no longer contains the reference and reports zero; the delete then breaks live consumers. | Enumerate namespaces dynamically from the platform at check time and report how many were scanned. | Treat the result as "no reference within the scanned scope", state that scope in the record, and derive the scope from a live listing rather than a written list. | 2026-09-07 |
