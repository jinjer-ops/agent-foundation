# 共有リポジトリの文体

読者は経緯を知らない。**作業の記録ではなく、対象物の説明として書く。**

この文書は「何を直すか」を規則IDで示す。**禁止されている表現そのものをここに例示しない**
（例示すると検査に自分で一致してしまい、規則の説明が規則違反になる）。
具体的な反例は [../../../tests/test_preflight.py](../../../tests/test_preflight.py) が
実行時に組み立てて検査へ渡す。反例が必要なときはそこを読む。

## 直す対象と、置き換える先

| 規則 | 直す対象 | 置き換える先 |
| --- | --- | --- |
| `C01` | 一つ前のやりとりを指す語、依頼・指摘への応答として書かれた文 | 変更した内容と理由だけを書く（「〜を追加した」「〜のため〜にした」） |
| `C02` | 一人称・二人称 | 主語を対象物か役割にする（「このスクリプトは」「実行者は」） |
| `C03` | 会話体の語尾 | 断定形か手順形にする（「〜する」「〜を実行する」） |
| `C04` | 案の記号や口頭合意を指す内部プロセス用語 | 決定内容と理由を書く。比較が必要なら却下理由まで書く |
| `C05` | 暫定判断を示す口語 | 現状の制約と、いつ見直すかを書く |
| `C06` | 相対日付 | `YYYY-MM-DD` の絶対日付 |
| `C07` | 期限も担当も無い予定 | 担当と期限を書く、issue にする、削除する |
| `C08` | 実態を確認せずに完了と書いた断定 | 実測日と証跡（ログ・件数・実行ID）を添える |
| `C09` | 作業に使った道具の痕跡 | 成果物の説明に書き換える |
| `P01` `P03` `P04` | 個人のメールアドレス、個人への言及、氏名 | 部署名・ロール名（例: リポジトリ管理者、データ基盤担当） |
| `L01`〜`L03` | 実在の利用者名を含む絶対パス | リポジトリ相対パス、環境変数、匿名化されたプレースホルダ |
| `S01`〜`S14` | 鍵・トークン・パスワード・認証ファイルの値 | 値ではなく在り処を書く。サンプルは完全ダミーにする |
| `T06` `T09` | 生データ・実行結果データ | コミットしない。匿名化サンプルに置き換える |

## 書き換えの型

| 型 | 内容 |
| --- | --- |
| 事実と解釈を分ける | 観測した事実に、未検証の因果を断定調で上乗せしない。理由が不明なら「特定できていない」と書く |
| 主語を対象物にする | 誰がやったかではなく、何がどうなるかを書く。担当が必要なときは役割で書く |
| 完了は証跡で書く | 「動く」ではなく「いつ・何件・どこで確認したか」を書く |
| 未確定を隠さない | 決めていないことを決めたように書かない。判断待ちは判断者を書く |
| 失敗時の次の一手を書く | エラー名だけを書かない。読者が取れる安全な操作を書く |
| 正本を1つにする | 同じ説明を2箇所に置かない。片方をリンクに置き換える |

## 確認の順序

1. この表に沿って書き直す。
2. [repo_checklist.md](repo_checklist.md) でリポジトリの体裁を点検する。
3. 機械検査を実行する。BLOCK を解消してから確定する。
4. WARN は件数・件数の多い規則・残す理由・残余リスクを PR 本文へ記録する。

**検査は補助である。** 日本語の実名を検出する辞書を持たないため、通過は「個人情報が無い」ことの
証明にならない。目で読む工程を省かない。
