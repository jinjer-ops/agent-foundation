# git-publish — 共有リポジトリへ入れる前の作法

## このスキルが解く問題

作業中の記録は、経緯を知っている読者を前提に書かれる。それをそのまま共有リポジトリへ入れると、
初見の読者が読めない文書と、秘密情報・個人情報・実在パスの混入が同時に起きる。

このスキルは、**書き方を直す手順**と、**機械検査で残りを止める仕組み**の2つで構成される。

## ルールの正本

共通運用ルールの正本は、索引リポジトリの `CONVENTIONS.md`（命名・フォルダ構成・Git 運用・秘密情報）である。
**このスキルはその実装であり、正本ではない。**

組織固有の判断（許可する組織アカウント、匿名化されたパスの形、履歴ブリーフのパス、運用ログのパス）は、
このリポジトリの `config/policy.json` に置く。**スクリプト本体に組織名・URL・端末パスを直書きしない。**

判定を変えるときは、①索引リポジトリの `CONVENTIONS.md` ②`config/policy.json` ③スクリプトと
`tests/` の順に更新する。

## 手順

1. **対象を確定する。** リモートの所有者、可視性、対象ブランチ、想定読者を確認する。
   公開範囲を変える操作は、実行者の明示的な承認を得てから行う。
2. **作業ツリーの状態を見る。** `git status --short`、差分、追跡ファイル、`.gitignore` を確認する。
   関係のない変更を巻き込まない。**対象パスだけを明示して stage する。**
3. **初見の読者向けに書き直す。** 判断の基準は [references/writing_register.md](references/writing_register.md)。
4. **機械検査を実行する。** 記憶に頼らず毎回実行する。

   ```bash
   python skills/git-publish/scripts/preflight.py --repo <対象リポジトリ> --scope staged
   ```

   初回公開時は `--scope all` で追跡ファイル全体を検査する。
   レシートの出力先は `--receipt-dir` で指定する。既定は一時ディレクトリで、
   **エージェントの home へは書き込まない。**
5. **BLOCK をすべて解消する。** 解消してから再実行する。
   **`--force` と抑制マーカーで恒久的な検出を通し続けない。** 判定を変える必要があるなら、
   上の「ルールの正本」の順序で規約と設定を先に直す。
6. **WARN は昇格させない。** ただし公開時は、**実測件数・件数の多い規則・残す理由・残余リスク**を
   PR 本文へ記録する。「検査を通した」とだけ書かない。
7. **1コミット1目的でコミットし、ブランチと PR を既定にする。** 既定ブランチへ直接 push しない。
8. **引き継ぎに何を書くか。** 変更したパス、実行した検査とその結果、リモートとブランチ、
   **意図的に検証していないこと**を書く。

## 検査が見るもの

| 種別 | 規則 | 例 |
| --- | --- | --- |
| 秘密情報 | `S01`〜`S14` | 鍵・トークン・パスワードの直書き、認証ファイル、`.env` |
| 個人情報 | `P01`〜`P04` | 個人のメールアドレス、個人への言及、著者名と一致する氏名 |
| 実在パス | `L01`〜`L04` | 利用者ディレクトリを含む絶対パス（匿名化された形は許容） |
| 文体 | `C01`〜`C09` | 会話文脈、一人称・二人称、会話体、内部プロセス用語、相対日付、未確定の口約束 |
| 構成 | `T01`〜`T14` | スクラッチ名、曖昧な版名、生データ、`README` / `.gitignore` / `docs` の欠如 |
| エンコーディング | `E01`〜`E03` | 種別ごとに要件が反転する（`.ps1` は BOM 必須、`.json` は BOM 禁止、`.sh` は LF） |

規則の本体は [scripts/preflight.py](scripts/preflight.py) にある。**規則の一覧をこの文書に複写しない**
（片方だけ更新される状態を作らないため）。

## 3つの恒久例外

規約が明示的に許容し、設定で表現しているものが3つある。詳細は
[../../config/POLICY.md](../../config/POLICY.md)、境界の確認は
[../../tests/test_preflight.py](../../tests/test_preflight.py)。

1. **組織アカウント識別子** — 台帳・remote・所有者の表記に必要なもの。理由付きの allowlist で1件ずつ許可する。
   個人名・個人アカウント名・個人のメールアドレスは対象外。
2. **匿名化されたパスの形** — 利用者名の位置を伏せた表記。実在の利用者名を含む絶対パスは検出する。
3. **原文保持の実装ブリーフ・完了記録** — 会話文脈の規則だけを外す。
   秘密情報・個人情報・実在パスの検査は継続する。

## 自動ゲート（登録していない）

**このフックは登録していない。commit / push は自動では止まらない。**
[hooks/git_publish_gate.py](../../hooks/git_publish_gate.py) は、検査レシートの有無と宛先ブランチで
commit / push / `gh pr create` を判定する PreToolUse フックだが、**強制は複数人で書く
リポジトリのための仕組み**であり、個人の記録用途では摩擦しか生まないため外した。
コードとテストは記録として残している。

**検査は手順として毎回実行する。** 実行していない場合は、その事実を引き継ぎと PR 本文に書く。
「検査を通した」と書かない。

以下は、再び登録する場合に効く仕様である。

- レシートは**これから確定する内容（tree）に対して**発行される。ファイルを直すと tree が変わり、
  レシートも無効になる。承認と対象が食い違わない。
- **レシートの置き場所は `config/policy.json` の `receipt_root` が正本。** 検査する側
  （`preflight.py` の既定）と読む側（ゲート）が同じ宣言を読む。場所を2箇所に書くと、
  書いた先と読む先が食い違い、何度検査しても通らなくなる。
- ゲートは場所を決められないとき（policy を読めない等）**通さない**。判定不能を素通しにしない。
- `git commit -a` は検査対象が確定しないため拒否される。`git add <path>` で明示する。
- 間接実行（シェルスクリプト内の git、コマンド置換）にはフックが効かない。その場合は手で検査する。
- 例外: `--force --reason "…"`（監査記録付きで1回通す）/ 対象外リポジトリを
  `~/.claude/hooks/git_publish_exempt.txt` に列挙する（雛形は
  [hooks/git_publish_exempt.txt.example](../../hooks/git_publish_exempt.txt.example)）。

フックが登録されているかは `agent-config-inventory` skill で確認する。**ファイルの存在は
稼働の証明ではない。** 登録されていない状態で「ゲートが止める」と書かない。

## 検査が見ないもの

- **日本語の実名を検出する辞書を持たない。** 個人名の照合は、対象リポジトリの著者名との一致だけである。
  **検査の通過は「個人情報が無い」ことの証明ではない。**
- 抽出できないバイナリ、画像の中の文字、リンク先の内容。
- 対象が多い場合は先頭のみを検査する（未検査の件数はレポートに出る）。分割して実行する。
